## Архитектурная логика компонентов

### 1. Каталог Model/ — Логика сетевых устройств (Бизнес-логика)
Отвечает за физические и сетевые параметры оборудования.

* **NetworkDevice**:
  * Моделирует системный блок / плату сетевого узла. Хранит сетевые реквизиты: имя хоста, IP-адрес, валидный заводской MAC-адрес (стандарт IEEE 802), тип устройства (`PC`, `Server`, `Switch`, `Router`) и статус питания `m_isOnline`.
  * **Аппаратные ограничения:** 
    * **PC:** 1 порт (`eth0`).
    * **Server:** 2 порта (`eth0`, `eth1`).
    * **Switch:** 8 портов (`FastEthernet 0/1` ... `FastEthernet 0/8`).
    * **Router:** 4 гигабитных порта (`GigabitEthernet 0/0` ... `GigabitEthernet 0/3`).
  * **Защита топологии:** Метод `hasFreePort()` запрещает подключать к узлу лишние провода сверх лимита, а `isConnectedTo()` предотвращает создание дублирующих линков между одними и теми же узлами.

---

### 2. Каталог Graphics/ — Графическое отображение (Представление)
Отвечает за пиксели, геометрию и взаимодействие с мышью.

* **NodeItem (наследник QGraphicsItem)**:
  * Отвечает за визуализацию сетевого узла на холсте. Отрисовывает векторную SVG-иконку устройства, текстовые подписи (имя и IP-адрес) и синюю пунктирную рамку при выделении (`isSelected()`).
  * Выступает в роли «датчика движения». Хранит список подключенных к нему кабелей `m_cables`. При смещении узла пользователем метод `itemChange()` ловит сигнал `ItemPositionChange` и автоматически вызывает `trackNodes()` у всех привязанных проводов, заставляя их следовать за узлом в реальном времени.

* **CableItem (наследник QGraphicsLineItem)**:
  * Отвечает за отрисовку физического кабеля связи с цветовой кодировкой стандарта:
    * 🔵 **Витая пара (TwistedPair)** — медь, 1 Гбит/с (`#2563EB`).
    * 🟠 **Оптоволокно (OpticalFiber)** — оптика, 10 Гбит/с (`#EA580C`).
    * ⚪ **Коаксиальный кабель (CoaxialCable)** — `#475569`.
    * 🔷 **Консольный кабель (ConsoleCable)** — `#0891B2`.

---

### 3. Каталог UI/ — Управление и интерфейс (Контроллер)
Связывает действия пользователя на экране с изменением состояния модели данных.

* **LanTopologySimulator (QMainWindow)**:
  * Главный контроллер всей системы. Управляет векторным холстом `ui.canvasView`, инициализирует точечную инженерную сетку (Dot Grid с шагом 30 px) и журнал событий (лог).
  * **Конечный автомат прокладки кабеля (`eventFilter`):** Перехватывает клики мыши по сцене:
    * Первый клик: запоминает стартовый узел `m_firstCableNode` и подсвечивает его рамкой.
    * Второй клик: передает пару узлов в диалог коммутации и фиксирует связь.

* **ConnectionDialog (QDialog)**:
  * Мастер коммутации портов. Динамически опрашивает модель `NetworkDevice` обоих устройств и выводит в выпадающие списки **только свободные порты**.
  * Smart Connect: По умолчанию сразу выбраны «Витая пара» и первые доступные интерфейсы. Пользователю достаточно нажать клавишу **Enter**, чтобы подтвердить соединение за доли секунды.

## Сценарий работы: Что происходит при прокладке кабеля (Data Flow)

Сквозной процесс взаимодействия слоёв при соединении узлов **PC1** и **Switch1**:

```text
[Пользователь] Кликает на PC1, затем на Switch1 при активном инструменте "Кабель"
      │
      ▼
1. КОНТРОЛЛЕР (LanTopologySimulator::eventFilter)
   Определяет два графических объекта NodeItem под курсором мыши.
      │
      ▼
2. ПРОВЕРКА МОДЕЛИ (NetworkDevice)
   Проверяет: есть ли у PC1 и Switch1 свободные интерфейсы (hasFreePort)?
   Не соединены ли они уже кабелем напрямую (isConnectedTo)?
      │
      ▼
3. ИНТЕРФЕЙС (ConnectionDialog)
   Открывается окно по координатам курсора:
   Выпадающие списки заполняются: PC1 -> ["eth0"], Switch1 -> ["Fa0/1", "Fa0/2"...].
   Пользователь подтверждает выбор нажатием [Enter].
      │
      ▼
4. ФИКСАЦИЯ В МОДЕЛИ (NetworkDevice::connectPort)
   - Порт eth0 у PC1 становится занятым (isOccupied = true) и привязывается к Switch1.
   - Порт Fa0/1 у Switch1 помечается занятым и привязывается к PC1.
      │
      ▼
5. ОТРИСОВКА В ГРАФИКЕ (CableItem)
   - Создается графический элемент линии связи выбранного цвета.
   - Кабель регистрируется в списках m_cables обоих NodeItem.
   - Метод cable->trackNodes() центрирует линию между иконками.
```

## Стандарт генерации MAC-адресов (IEEE 802)

В симуляторе реализован генератор валидных заводских Unicast MAC-адресов.  
Формат адреса: `XX : XX : XX : XX : XX : XX` (6 байт / 48 бит).

### Управляющие биты в 1-м байте (Octet 0):
Тип адреса определяется двумя младшими битами самого первого байта:

* **Бит 0 — I/G (Individual / Group):**
  * `0` — **Unicast**: индивидуальный адрес для передачи пакета конкретному узлу.
  * `1` — **Multicast / Broadcast**: групповая/широковещательная рассылка.
* **Бит 1 — U/L (Universal / Local):**
  * `0` — **Universal**: всемирно уникальный адрес, присвоенный производителем (OUI).
  * `1` — **Locally Administered**: локально/программно назначенный адрес.

### Программная маска:
Для гарантии генерации честного заводского Unicast-адреса на первый байт накладывается побитовая маска:
```cpp
mac[0] &= 0xFC; // Обнуляет биты 0 и 1: 0xFC = 11111100 (двоичный вид)
```
